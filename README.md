# Mock Gen

This tool produces mocks for all interfaces in a file.

If compiled it can be used as a command line tool:

```shell
mock_gen [flags] <path_to_go_source_file>
```

It can be also executed using go run:

```bash
go run <path_mock_gen>/main.go -- [flags] <path_to_go_source_file>
```

It will produce a file with at `./test/<source_file_name>_mocks.go`.

## Options

- `--output, -o` - Specify a custom output file path (optional)
- `--generate-return-handler` - Generates a single return handler field (e.g., Method_return func(...)) that allows dynamic return value handling
- `--thread-safe` - Adds a mutex to the mock struct and makes all methods thread-safe
- `--template, -t` - Path to a custom Go template file to use instead of the built-in mock template
- `--no-header-note` - Skips adding the "Code generated" header comment

## Example

With the following source file:
```go
package product

type Service interface {
	GetProductByID(ctx context.Context, productID model.ProductID) model.Product
}
```
It will produce the following mock:
```go
package test

import "your/project/internal/service/product/model"

type ServiceMock struct {
	GetProductByID_calls           int
	GetProductByID_param_context   context.Context
	GetProductByID_param_productID model.ProductID
	GetProductByID_return_product  model.Product
}

func (this *ServiceMock) GetProductByID(param1 context.Context, param2 model.ProductID) model.Product {
	this.GetProductByID_calls++
	this.GetProductByID_param_context = param1
	this.GetProductByID_param_productID = param2
	return this.GetProductByID_return_product
}
```

## Thread-Safe Example

When using the `--thread-safe` option:

```shell
mock_gen --thread-safe <path_to_go_source_file>
```

The generated mock will include a mutex and all methods will be thread-safe:
```go
package test

import (
	"sync"
	
	"your/project/internal/service/product/model"
)

type ServiceMock struct {
	mu sync.Mutex

	GetProductByID_calls           int
	GetProductByID_param_context   context.Context
	GetProductByID_param_productID model.ProductID
	GetProductByID_return_product  model.Product
}

func (this *ServiceMock) GetProductByID(param1 context.Context, param2 model.ProductID) model.Product {
	this.mu.Lock()
	defer this.mu.Unlock()
	this.GetProductByID_calls++
	this.GetProductByID_param_context = param1
	this.GetProductByID_param_productID = param2
	return this.GetProductByID_return_product
}
```

## Custom Templates

By default, mock_gen generates standard mocks with call counters, parameter capture, and return values. You can customize the output by providing your own Go `text/template` using the `--template` flag.

### How It Works

1. mock_gen parses Go interfaces and collects a structured data model (`MockData`)
2. By default, this data is rendered using a built-in template that produces standard mocks
3. With `--template`, you can provide your own Go `text/template` to generate any output
4. The output is always run through `go/format.Source` (gofmt), so the template doesn't need perfect formatting, but it must produce valid Go code

### Data Model Reference

Your custom template receives a `MockData` struct with the following fields:

```go
type MockData struct {
    HeaderNote string       // "// Code generated by MockGen. DO NOT EDIT.\n\n" or ""
    Imports    ImportsData
    Interfaces []InterfaceData
    Options    Options
}

type ImportsData struct {
    StdImports    []string   // Standard library imports (e.g., "context", "sync")
    NonStdImports []string   // Third-party/module imports (e.g., "github.com/foo/bar")
}

type InterfaceData struct {
    Name     string       // Original interface name (e.g., "Service")
    MockName string       // Mock struct name (e.g., "ServiceMock")
    Methods  []MethodData
}

type MethodData struct {
    Name          string           // Method name (e.g., "Add")
    CallsField    string           // Call counter field name (e.g., "Add_calls")
    Params        []FieldData      // Parameter fields
    ReturnHandler *ReturnHandlerData // Non-nil when GenerateReturnHandler is true and method has returns
    Returns       []FieldData      // Return value fields
    Signature     SignatureData    // Rendered method signature parts
    Getters       *GetterData      // Non-nil when MakeThreadSafe is true
}

type FieldData struct {
    Name string  // Field name (e.g., "Add_param_one")
    Type string  // Go type (e.g., "int", "*http.Request")
}

type ReturnHandlerData struct {
    FieldName   string  // e.g., "Add_return"
    ParamTypes  string  // e.g., "int, string"
    ReturnTypes string  // e.g., "string, error"
}

type SignatureData struct {
    Params       string    // Rendered params: "one int, two string"
    Returns      string    // Rendered returns: " string" or " (name string, e error)"
    ParamNames   []string  // Just names: ["one", "two"]
    ReturnFields []string  // Qualified return fields: ["this.Add_return_string"]
}

type GetterData struct {
    CallsGetter   GetterMethod
    ParamGetters  []GetterMethod
    ReturnSetters []SetterMethod
}

type GetterMethod struct {
    MethodName string  // Public getter name (e.g., "Add_calls")
    FieldName  string  // Private field name (e.g., "add_calls")
    ReturnType string
}

type SetterMethod struct {
    MethodName string
    FieldName  string
    ParamType  string
}

type Options struct {
    GenerateReturnHandler bool
    MakeThreadSafe        bool
    AddHeaderNote         bool
    CustomTemplate        string
}
```

### Example: List Interface Names

A simple custom template that lists all discovered interfaces:

```
mock_gen --template interfaces.tmpl -o output.go service.go
```

With `interfaces.tmpl`:

```go
package test

// Interfaces found:
{{range .Interfaces}}// - {{.Name}} ({{len .Methods}} methods)
{{end}}
```

### Example: Spy Pattern

A more complex template that generates spies instead of mocks. Spies record all calls in a slice:

Create `spy.tmpl`:

```go
package test

{{if or .Imports.StdImports .Imports.NonStdImports}}import (
{{range .Imports.StdImports}}	{{.}}
{{end}}{{if and .Imports.StdImports .Imports.NonStdImports}}
{{end}}{{range .Imports.NonStdImports}}	{{.}}
{{end}})
{{end}}

{{range $iface := .Interfaces}}
type {{$iface.MockName}}Call struct {
	Method string
	Args   []any
}

type {{$iface.MockName}} struct {
	Calls []{{$iface.MockName}}Call
{{range $iface.Methods}}{{range .Returns}}	{{.Name}} {{.Type}}
{{end}}{{end}}}

{{range $method := $iface.Methods}}func (this *{{$iface.MockName}}) {{$method.Name}}({{$method.Signature.Params}}){{$method.Signature.Returns}} {
	this.Calls = append(this.Calls, {{$iface.MockName}}Call{Method: "{{$method.Name}}", Args: []any{ {{range $i, $pn := $method.Signature.ParamNames}}{{if $i}}, {{end}}{{$pn}}{{end}} }})
{{if $method.Returns}}	return {{range $i, $rf := $method.Signature.ReturnFields}}{{if $i}}, {{end}}{{$rf}}{{end}}
{{end}}}
{{end}}{{end}}
```

Generate spies:

```shell
mock_gen --template spy.tmpl -o service_spy.go service.go
```

This produces mocks that record every method call with all arguments in a `Calls` slice, allowing you to verify call order and arguments in tests.

### Accessing the Built-in Template

The built-in template can be accessed programmatically via `DefaultTemplate()`. This function returns the template string used for standard mock generation, which can serve as a starting point for creating custom templates:

```go
import "github.com/yourusername/mock_gen"

template := mock_gen.DefaultTemplate()
// Modify template as needed
```
