# Mock Gen

A Go tool that generates mock implementations for all interfaces in a source file.

The generated mock exposes two namespaces for tests to interact with:

- `mock.Calls()` — inspection: one method per interface method, each returning per-call records.
- `mock.On()` — configuration: one method per interface method, each returning a config object that arms return values or installs dynamic handlers.

The mock itself implements the source interface directly, so the system under test sees `Service`, not `ServiceMock`.

The input file must be inside a Go module (a directory tree containing a `go.mod` file). mock_gen resolves types and imports relative to the source file's module, so it can be invoked from any working directory.

## Installation

```shell
go install github.com/ArtHustle/mock_gen/cmd/mock_gen@latest
```

## Usage

```shell
mock_gen [flags] <source_file.go | dir>
```

The input is either a single `.go` file or a directory. With a file, the output is written to `./test/<source_file>_mock.go` relative to the input file. With a directory, every non-test `.go` file in it is scanned and one mock is generated per source file that declares at least one interface; files without interfaces and `*_test.go` files are skipped.

If running the generator would produce a file byte-identical to what's already on disk, the write is skipped — preserves mtime for build caches and avoids spurious git noise during `go generate` loops.

## Options

| Flag | Short | Description |
|------|-------|-------------|
| `--output` | `-o` | Custom output file path (single-file mode only) |
| `--async` | | Makes the mock safe for use from goroutines: `sync.Mutex` guards all generated state; methods with returns use the snapshot pattern so user code never runs under the lock; every `Calls()` namespace gains `WaitForCount(n, timeout)` and `WaitForCall(predicate, timeout)` for asserting on calls made by background goroutines. |
| `--inspect-entry` | | Override the inspection entry name (default `Calls`). Use when the source interface has a method named `Calls`. |
| `--config-entry` | | Override the configuration entry name (default `On`). Use when the source interface has a method named `On`. |
| `--template` | `-t` | Path to a custom Go `text/template` file for code generation |
| `--no-header-note` | | Omits the `// Code generated by MockGen. DO NOT EDIT.` header |

## Example

Given `service.go`:

```go
package product

import "context"

type Service interface {
    GetProductByID(ctx context.Context, id string) (Product, error)
}
```

Running:

```shell
mock_gen --async service.go
```

Produces a mock in `./test/service_mock.go` that you use like this:

```go
mock := test.NewServiceMock()

// Configure: arm static returns
mock.On().GetProductByID().ReturnAll(Product{ID: "abc"}, nil)

// Override just one return value, keep others armed
mock.On().GetProductByID().Return().Error(errors.New("not found"))

// Or install a dynamic handler
mock.On().GetProductByID().ReturnCustom(func(ctx context.Context, id string) (Product, error) {
    if id == "missing" {
        return Product{}, errors.New("not found")
    }
    return Product{ID: id}, nil
})

// System under test calls mock.GetProductByID(ctx, "abc") through the interface...

// Inspect
require.Equal(t, 1, mock.Calls().GetProductByID().Count())

c := mock.Calls().GetProductByID().Last()
require.Equal(t, "abc", c.Param.Id)
require.Equal(t, "abc", c.Return.Product.ID)  // what the mock actually returned
require.NoError(t, c.Return.Error)
```

Same-package types, imported types (with collision-resolving aliases), generics, function-typed params/returns, inline `struct{...}` and `interface{...}` types, and embedded interfaces all render correctly. Empty `interface{}` renders as `any`.

## The Two Namespaces

### `Calls()` — inspection

`mock.Calls()` returns a namespace where every interface method becomes an accessor. Each accessor returns a per-method object with:

- **`Count() int`** — number of recorded calls.
- **`At(i int) Call`** — i-th recorded call. Negative `i` counts from the end (`-1` is the last, `-2` second-to-last). Out-of-range panics with a descriptive message that includes the input index, resolved index, and log length.
- **`Last() Call`** — sugar for `At(-1)`.
- **`All() []Call`** — defensive copy of the full log.
- **`Reset()`** — clears this method's log. Does **not** clear the cross-method timeline; use `mock.Reset()` or `mock.Calls().Reset()` for that.
- **`PendingStubs() int`** — number of unconsumed `Once` entries in this method's queue. `Always` does not count (it is a fallback, not a single-shot entry).
- **`Any(func(Call) bool) bool`** — true iff at least one recorded call satisfies the predicate. See [Filtering recorded calls](#filtering-recorded-calls).
- **`Filter(func(Call) bool) []Call`** — every recorded call satisfying the predicate, in invocation order. Returns an empty non-nil slice on no match.

Each `Call` has `Index`, `GlobalIndex`, `Param`, and `Return` sub-fields. `Param` and `Return` hold the recorded args (in) and returned values (out). `Index` is the per-method position; `GlobalIndex` is mock-wide — see [Timeline and ordering](#timeline-and-ordering).

`mock.Calls().Reset()` clears every method's log and the cross-method timeline, without touching configured returns or handlers.

`mock.Calls().PendingStubs()` sums unconsumed `Once` entries across all methods — both unconditional and `When`-conditional.

`mock.Calls().Verify(t)` calls `t.Helper()` and, if any method has unconsumed stubs, calls `t.Errorf` with a per-method breakdown (e.g. `"ServiceMock: 2 unconsumed stubs (Get: 2)"`). It does not call `t.Fatal`, so other teardown checks still run. This is part of the stable contract.

`mock.Calls().Timeline()` returns every recorded call across all methods in invocation order. `mock.Calls().AssertOrder(t, c1, c2, ...)` fails the test if the given call handles weren't recorded in the given order. See [Timeline and ordering](#timeline-and-ordering).

### `On()` — configuration

`mock.On()` returns a namespace where every interface method becomes an accessor. Each accessor returns a per-method config object with:

- **`ReturnAll(...)`** — set all static return values positionally.
- **`Return().X(value)`** — override just the `X` return (where `X` is the title-cased return name). Per-slot setters chain, so `Return().X(a).Y(b)` works as one statement. The two-statement form still works. Subsequent `ReturnAll(...)` overwrites every slot positionally.
- **`ReturnCustom(func(...))`** — install a dynamic function called instead of returning the static values.
- **`Once().Return().X(value)`** — queue a single-shot return. Each `Once()` appends one entry to the per-method FIFO queue. Calls consume the queue head first.
- **`Always().Return().X(value)`** — install (or replace) a fallback return used after the queue is exhausted. Multiple `Always()` calls are allowed; the last one wins.
- **`When(func(<ParamType>) bool)`** — register a conditional arming fired only on calls whose Param satisfies the predicate. The returned namespace exposes `Once()` and `Always()`. See [Argument matchers](#argument-matchers).
- **`Reset()`** — clears `ReturnAll`-set values, `Return()`-set values, the `ReturnCustom` handler, the `Once` queue, the `Always` fallback, and any `When` conditionals for this method.

`mock.On().Reset()` clears every method's config at once, without touching the call logs.

`mock.Reset()` clears both — equivalent to `mock.Calls().Reset()` followed by `mock.On().Reset()`.

## Sequenced stubs

For tests that need different return values on successive calls, `Once()` and `Always()` build a per-method FIFO queue:

```go
// Queue two specific returns, then fall back to a steady state:
m.On().GetProductByID().Once().Return().Product(Product{ID: "abc"}).Err(nil)
m.On().GetProductByID().Once().Return().Err(errors.New("transient"))
m.On().GetProductByID().Always().Return().Product(defaultProduct).Err(nil)
```

**Dispatch order per call:**
1. Pop the head of the queue if non-empty (`Once` entries, FIFO).
2. Otherwise use the `Always` fallback if set.
3. Otherwise fall through to static (`ReturnAll` / `Return().X(...)`) values.
4. Otherwise zero values.

**Rules:**
- `Once()` and `Always()` may be mixed freely — add any number of `Once()` entries and any number of `Always()` replacements in any order.
- Mixing the sticky path (`Return()`, `ReturnAll`, `ReturnCustom`) with the queued path (`Once`, `Always`) **panics** with a direction-specific message — `"cannot set sticky return while Once()/Always() entries are armed"` or `"cannot arm Once()/Always() while a sticky return is set"`. Call `Reset()` first if you need to switch modes mid-test.
- `Always()` does **not** count as a pending stub — it is a fallback, not a single-shot entry.
- Per-slot setters chain: `Once().Return().X(a).Y(b).Err(nil)` sets all three slots in one statement. Last write within a single entry wins.

## Argument matchers

For tests that want different returns depending on the call's arguments, `When(pred)` arms a conditional stub set:

```go
// VIP user gets a specific id; default fallback for everyone else.
m.On().Send().
    When(func(p ServiceMockSendParam) bool { return p.Email == "vip@example.com" }).
    Once().Return().Id("vip-id").Err(nil)

m.On().Send().Always().Return().Id("default").Err(nil)
```

The predicate is typed over the per-method `Param` struct (`ServiceMockSendParam` above), so refactors to the source interface surface as compile errors rather than runtime mismatches.

The namespace returned by `When(pred)` exposes exactly two methods:

- **`Once()`** — append a single-shot stub to this conditional's queue.
- **`Always()`** — install (or replace) a fallback stub for this conditional.

There is no conditional `Return()` / `ReturnAll()` / `ReturnCustom()`. A "conditional sticky" is just `When(p).Always()`; a "conditional handler" is expressible via an unconditional `ReturnCustom` whose body switches on the param.

**Multiple armings on one predicate** — capture the namespace in a local var:

```go
cond := m.On().Send().When(func(p ServiceMockSendParam) bool { return p.Email == "ratelimited@example.com" })
cond.Once().Return().Err(rateLimitedErr) // first call
cond.Always().Return().Id("ok").Err(nil) // subsequent matching calls
```

**Dispatch order per call:**

1. Walk this method's `When` conditionals in registration order. Collect all matching indices.
2. If **two or more match**, panic with a message naming the mock, method, and the indices of the first two matching predicates — e.g. `ServiceMock.Send: call matched 2 When predicates (indices 0 and 1); refine the predicates or remove the overlap`.
3. If **exactly one matches**, dispatch into that conditional's queue, then its `Always` fallback. If both are empty (the conditional matched but is exhausted), fall through to step 4.
4. Otherwise, use the unconditional path (queue → `Always` → sticky → zero values), as documented in [Sequenced stubs](#sequenced-stubs).
5. If `ReturnCustom` is installed on the unconditional path, the handler wins over the static-stub source from any of the above steps. `ReturnCustom` does not exist on conditionals.

**Rules:**

- Conditional and unconditional registrations may coexist on the same method. `When(...)` is for special cases; unconditional `Once`/`Always`/`Return` is for the default. No panic at registration; only at call time if two predicates overlap.
- Conditional `Once` entries count toward `PendingStubs()` and the `Verify(t)` breakdown.
- `m.On().<Method>().Reset()` drains conditionals along with the unconditional cfg. `m.Reset()` does the same for every method.
- Predicate evaluation under `--async` runs inside the existing snapshot lock — no new lock boundaries, no extra contention.

## Verification at teardown

After the system under test runs, assert that all queued stubs were consumed:

```go
// In TestFoo, or a t.Cleanup / defer:
m.Calls().Verify(t)
```

`Verify(t)` calls `t.Helper()` and, if any method has unconsumed `Once` entries, calls `t.Errorf` with a per-method breakdown. It does not call `t.Fatal` so other teardown checks still run.

Check counts programmatically:

```go
// Unconsumed Once entries for one method:
n := m.Calls().GetProductByID().PendingStubs()

// Sum across all methods:
total := m.Calls().PendingStubs()
```

Both `PendingStubs()` and `Verify(t)` are part of the stable API contract.

## Call recording

Every call is recorded:

- **Params** captured before the method body runs (so a panicking handler still leaves the call recorded).
- **Returns** captured after — they reflect what the handler actually returned, or the armed static values if no handler is installed. If the handler panics, the recorded entry's `Return` keeps its zero values.

```go
// Multiple calls, then inspect each:
for i, c := range mock.Calls().Send().All() {
    fmt.Printf("call %d: email=%q returned id=%q err=%v\n",
        i, c.Param.Email, c.Return.Id, c.Return.Err)
}

// Last call's outcome:
last := mock.Calls().Send().Last()
require.Equal(t, "user@x.com", last.Param.Email)
require.NoError(t, last.Return.Err)
```

Each `Call` also has `Index int` (per-method position) and `GlobalIndex int` (mock-wide position) — see [Timeline and ordering](#timeline-and-ordering).

## Filtering recorded calls

Each per-method `Calls()` namespace exposes `Any(pred)` and `Filter(pred)` for predicate-based assertions:

```go
// Was Send ever called with email == "vip@x.com" AND returned a non-nil error?
if mock.Calls().Send().Any(func(c ServiceMockSendCall) bool {
    return c.Param.Email == "vip@x.com" && c.Return.Err != nil
}) {
    t.Fatal("VIP send should not have errored")
}

// Collect every call that returned an error:
errored := mock.Calls().Send().Filter(func(c ServiceMockSendCall) bool {
    return c.Return.Err != nil
})
require.Len(t, errored, 2)
```

The predicate sees the full `<CallType>` value — `Index`, `GlobalIndex`, `Param`, and `Return`. This is the deliberate asymmetry with v0.13's `When(pred)`: `When` runs at dispatch time and so can't see `Return`; `Any`/`Filter` run on already-recorded calls and have it.

- `Filter` returns an empty non-nil slice on no match.
- Passing a `nil` predicate panics with `"<helper>.Any: predicate is nil"` / `"<helper>.Filter: predicate is nil"`. Silent match-all would hide accidental nils.
- Under `--async`, both methods snapshot the log under the mutex and run the predicate after release. Predicates may safely call back into the mock without deadlocking.

## Timeline and ordering

Every recorded call carries a mock-wide `GlobalIndex int` alongside its per-method `Index`. The counter ticks once per call across all methods, so the timeline answers ordering questions that the per-method view cannot:

```go
// Did Send happen before Close?
if !mock.Calls().Send().Last().HappenedBefore(mock.Calls().Close().Last()) {
    t.Fatal("Send must precede Close")
}

// Or assert a sequence in one call:
mock.Calls().AssertOrder(t,
    mock.Calls().Send().At(0),
    mock.Calls().Send().At(1),
    mock.Calls().Close().Last(),
)
```

- `HappenedBefore(other)` is a strict less-than over `GlobalIndex`; `c.HappenedBefore(c)` is false.
- `HappenedBefore` accepts any value satisfying the per-mock `<MockName>Call` interface — every per-method `<CallType>` and `<MockName>TimelineEntry` value satisfies it, so comparisons across different methods compose without type assertions.
- `AssertOrder(t, entries...)` reuses the same `VerifyT` interface as `Verify(t)` (`Helper()`, `Errorf(...)`). Fails on the first out-of-order pair with a message including the entry indices and their `GlobalIndex` values. Empty or one-entry input is a no-op.

The full timeline is also available as a slice:

```go
tl := mock.Calls().Timeline()
for _, e := range tl {
    fmt.Printf("global #%d: %s[%d]\n", e.GlobalIndex, e.Method, e.Index)
}
```

Each `<MockName>TimelineEntry` has `Method string`, `Index int` (per-method position at recording time), and `GlobalIndex int`. The returned slice is a defensive copy.

`mock.Reset()` and `mock.Calls().Reset()` clear the timeline and reset the counter to zero. Per-method `mock.Calls().<Method>().Reset()` does **not** clear the timeline — it records that the call happened, and that fact stays true even after the per-method log is cleared. Callers who want a full wipe should use the mock-level or `Calls()`-level Reset.

## Async-safe mocks

With `--async`, the mock is safe to use from goroutines:

- A `sync.Mutex` guards all generated state. The exported API is identical with or without `--async` — flipping it on only adds internal locking and the WaitFor* methods below.
- Methods with returns use the snapshot pattern: lock, append the call + snapshot config, unlock, run handler / fall back to static returns, lock, write the `Return` back into the recorded entry, unlock. The lock is never held while user code (handler) runs.
- **Arming should not race with consumption.** Configure all `On()` chains before launching the system under test. Each per-slot setter (`Return().X(v)`) takes the mutex independently, so a chain like `Once().Return().X(a).Y(b)` is not atomic w.r.t. a goroutine simultaneously *consuming* the queue — a partially-armed entry can be dispatched. Setting up stubs from a single goroutine before invocation begins avoids this entirely.
- Every per-method `Calls()` namespace gains two waiters for asserting on calls made by background goroutines:

```go
// Block until at least 3 calls have been recorded (or 100ms elapses).
if err := mock.Calls().Send().WaitForCount(3, 100*time.Millisecond); err != nil {
    t.Fatal(err)
}

// Block until a call matches a predicate. Predicate sees both Param and Return.
err := mock.Calls().Send().WaitForCall(
    func(c ServiceMockSendCall) bool {
        return c.Param.Email == "target@x.com" && c.Return.Err == nil
    },
    100*time.Millisecond,
)
```

Both poll every 1ms. On timeout they return a descriptive `error` (not `panic`) so tests can do inverse assertions ("should NOT be called within X").

```go
mock := test.NewServiceMock()
mock.On().Send().ReturnCustom(/* ... */)

// 100 goroutines calling Send concurrently is safe:
for i := 0; i < 100; i++ {
    go mock.Send(ctx, fmt.Sprintf("user-%d", i))
}
```

## Entry-point collisions

If the source interface declares a method literally named `Calls`, `On`, or `Reset`, the generator errors out with a message pointing at the offender:

- `Calls()` and `On()` collisions can be resolved by overriding the entry name via `--inspect-entry NAME` (or `--config-entry NAME`).
- `Reset()` cannot be overridden — the source interface must be modified.

```shell
# source has `Calls()` method:
mock_gen --inspect-entry Inspect svc.go

# usage becomes mock.Inspect().X().Count() etc.
```

## Custom templates

You can replace the built-in template with your own Go `text/template` via `--template`. The template receives a `MockData` value and its output is run through `gofmt`.

```go
type MockData struct {
    HeaderNote string
    Imports    ImportsData
    Interfaces []InterfaceData
    Options    Options
}

type InterfaceData struct {
    Name             string  // source interface name, e.g. "Service"
    MockName         string  // generated mock type, e.g. "ServiceMock"
    InspectEntryName string  // "Calls" by default
    ConfigEntryName  string  // "On" by default
    InspectType      string  // "serviceMockCalls"
    ConfigType       string  // "serviceMockOn"
    CallsHelperType  string  // per-mock generic inspection helper, e.g. "serviceMockCallsHelper"
    Methods          []MethodData
}

type MethodData struct {
    Name                    string
    Signature               SignatureData
    CallType                string  // "ServiceMockSendCall"
    ParamType               string  // "ServiceMockSendParam"
    ReturnType              string  // "ServiceMockSendReturn"
    ParamFields             []FieldData
    ReturnFields            []FieldData
    LogField                string  // "sendLog"
    CfgField                string  // "sendCfg"
    CfgType                 string  // "serviceMockSendCfg"
    CfgReturnFields         []FieldData
    HandlerFieldName        string  // "handler" (empty when no returns)
    HandlerType             string  // "func(...) (...)"
    InspectMethodType       string  // "serviceMockSendCalls"
    ConfigMethodType        string  // "serviceMockSendOn"
    PerReturnSetterType     string  // "serviceMockSendReturn" (empty when no returns)
    ReturnsSetterName       string  // "ReturnAll" (empty when no returns)
    CustomReturnSetterName  string  // "ReturnCustom" (empty when no returns)
    IndividualReturnSetters []SetterMethod  // MethodName is the bare return name, e.g. "Id"
    StubType                string  // per-queue-entry struct type, e.g. "serviceMockSendStub" (empty when no returns)
    OnceType                string  // namespace returned by On().<Method>().Once(), e.g. "serviceMockSendOnce" (empty when no returns)
    AlwaysType              string  // namespace returned by On().<Method>().Always(), e.g. "serviceMockSendAlways" (empty when no returns)
}
```

See `DefaultTemplate()` for the built-in template — copy it and modify to customize.

## `go generate` integration

Add a `//go:generate` directive at the top of each source file containing interfaces you want to mock:

```go
//go:generate mock_gen --async $GOFILE

package service

type Service interface {
    Send(ctx context.Context, email string) error
}
```

Then regenerate from the project root:

```shell
go generate ./...
```

For a whole-tree regeneration without per-file directives, the CLI's recursive mode works directly:

```shell
mock_gen --async ./...
```

This walks the current directory recursively, generates one mock per source file that declares at least one interface, and writes each into a sibling `test/` directory. Directories named `test`, `vendor`, `node_modules`, or beginning with `.` are skipped (they don't get re-fed as input). Generated files are byte-compared before writing — unchanged files are not rewritten, preserving mtime for build caches.

## Programmatic usage

```go
import mock_gen "github.com/ArtHustle/mock_gen"

content, err := mock_gen.GenerateMockFileWithOptions("service.go", mock_gen.Options{
    Async: true,
    AddHeaderNote:  true,
})

// Or from source string (tests, embedding):
content, err := mock_gen.GenerateMockContentWithOptions(sourceCode, mock_gen.Options{})
```

## Versioning

v0.14.0 adds cross-method ordering and per-method call predicates. **Additive, backward-compatible.**

- **No breaking changes.** All v0.13 code keeps working without modification.
- **New API**:
  - Mock-level: `mock.Calls().Timeline() []<MockName>TimelineEntry` and `mock.Calls().AssertOrder(t, c1, c2, ...)`.
  - Per-method (via the existing generic CallsHelper): `mock.Calls().<Method>().Any(pred)` and `Filter(pred)`.
  - Every per-method `<CallType>` gains a `GlobalIndex int` field plus `Global() int` and `HappenedBefore(other <MockName>Call) bool` methods. A new per-mock `<MockName>Call` interface unifies cross-type comparison; `<MockName>TimelineEntry` also implements it.
- **Behavior**: mock-level `Reset()` and `Calls().Reset()` clear the timeline and reset the mock-wide call counter to zero. Per-method `Calls().<Method>().Reset()` only clears that method's log, intentionally — the timeline records that a call happened, and that fact stays true even after the per-method log is cleared.
- **Custom-template authors**: four new `InterfaceData` fields — `TimelineEntryType`, `CallInterfaceType`, `TimelineLogField`, `GlobalCounterField` — populate every generated mock. No new `MethodData` fields; the per-`<CallType>` additions (`GlobalIndex` field, `Global`/`HappenedBefore` methods) are templated inline from existing context.

v0.13.0 adds typed-predicate argument matchers via `When(pred)`. **Additive, backward-compatible.**

- **No breaking changes.** All v0.12 code keeps working without modification.
- **New API**: `When(func(<ParamType>) bool)` on the per-method config namespace. The returned conditional namespace exposes `Once()` and `Always()`. See [Argument matchers](#argument-matchers).
- **One new runtime panic** (unreachable by v0.12 code): if two `When` predicates both match the same incoming call, the call panics with a message naming the mock, method, and the indices of the colliding predicates. Refine the predicates or remove the overlap to recover.
- **Custom-template authors**: two new `MethodData` fields — `ConditionalType` and `OnConditionalType` — are populated for methods with return values and empty otherwise. `ConditionalType` is the per-method conditional struct (e.g. `serviceMockSendConditional`) and `OnConditionalType` is the conditional namespace returned by `When(pred)` (e.g. `serviceMockSendOnWhen`). Authors of templates that copy `DefaultTemplate()` get the new code automatically; authors of from-scratch templates can ignore it (they own their own emission).

v0.12.0 adds sequenced stubs and teardown verification. **Additive, backward-compatible.**

- **No breaking changes.** All v0.11 code keeps working without modification.
- **One behavior change** (unreachable by v0.11 code): mixing the sticky path (`Return()`, `ReturnAll`, `ReturnCustom`) with the queued path (`Once`, `Always`) now panics. Code that never called `Once()` or `Always()` is unaffected.
- **Additive ergonomic**: per-slot setters (`Return().X(value)`) now return the setter type, so `Return().X(a).Y(b)` chains as one statement. The two-statement form keeps working.
- **New API**: `Once()`, `Always()` on per-method config; `PendingStubs()` on per-method and mock-level inspect; `Verify(t)` on mock-level inspect.
- **Custom-template authors**:
  - Three new `MethodData` fields — `StubType`, `OnceType`, `AlwaysType` — are populated for methods with return values and empty otherwise.
  - One new `InterfaceData` field — `CallsHelperType` — names a per-mock generic helper (e.g. `serviceMockCallsHelper[CT any]`) that the default template emits once per mock and embeds into each per-method `<Method>Calls` type. This is the source of the `Count`/`At`/`Last`/`All`/`Reset`/`PendingStubs`/`WaitForCount`/`WaitForCall` method set. Authors of templates that copy `DefaultTemplate()` get this automatically; authors of from-scratch templates can ignore it (they own their own emission).

v0.11.0 renamed the per-method config setters. Migration:

| v0.10.x | v0.11.0 |
|---|---|
| `mock.On().Send().Returns(id, err)` | `mock.On().Send().ReturnAll(id, err)` |
| `mock.On().Send().ReturnsId(id)` | `mock.On().Send().Return().Id(id)` |
| `mock.On().Send().ReturnsErr(err)` | `mock.On().Send().Return().Err(err)` |
| `mock.On().Send().Handler(fn)` | `mock.On().Send().ReturnCustom(fn)` |

`Reset()` is unchanged. Methods with no returns still expose only `Reset()`.
Custom-template authors: `MethodData.ReturnsSetterName` is now `"ReturnAll"` (was `"Returns"`); per-return setter `MethodName` is now the bare return name (e.g. `"Id"`, was `"ReturnsId"`); new fields `MethodData.CustomReturnSetterName` (`"ReturnCustom"`) and `MethodData.PerReturnSetterType` (e.g. `"serviceMockSendReturn"`) expose the renamed handler setter and the new per-return setter type respectively.

v0.10.0 renamed `--thread-safe` to `--async` (and `Options.MakeThreadSafe` to `Options.Async`). Behavior under the old flag is unchanged; under the new flag, every `Calls()` namespace also gains `WaitForCount(n, timeout)` and `WaitForCall(predicate, timeout)`. Migration: `s/--thread-safe/--async/g` in `//go:generate` directives, `s/MakeThreadSafe/Async/g` in programmatic uses.

v0.9.0 is a complete API rewrite from v0.8.x. The old snake-case accessors (`Send_calls()`, `Send_call(i)`, `Send_return(handler)`) are gone. Migration:

| v0.8.x | v0.9.0 |
|---|---|
